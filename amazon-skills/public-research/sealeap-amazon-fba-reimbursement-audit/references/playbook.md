# FBA 赔偿复核手册

## 三个不同队列

| 队列 | 需要的证据 | 下一步 |
|---|---|---|
| 成本估值偏差 | 单位匹配的成本证明、平台当前估值、币种 | 准备成本更新草稿 |
| 已赔金额复核 | 损失事件、已赔净额、Reimbursement ID、窗口依据 | 核对政策基数与差额 |
| 未赔损失 | 事件完整性、自动赔偿状态、已找回/取消记录 | 确认是否具备申报条件 |

金额为零必须有报告证明；空值不能当未赔。一个事件分多次赔偿时先净额对账，保留流水 ID 与加总过程。无法确定是否发生在顾客订单前，状态 HOLD。

## 材料包

以事件 ID 关联：商品身份、损失时间和数量、当前政策及查询日期、成本币种/可售单位、证明页码、平台估值、赔偿净流水、申请理由。只截取与本案有关的材料并遮蔽不必要的个人信息。

首次被拒后先读具体原因，补齐凭证或单位差异；不连续调高数字尝试。复核窗口和更新次数来自当前账户说明，不采用网络文章的固定天数或审核时长。

## 验收

同一事件不重复；包装单位相同；税费范围明确；订单前后不混算；差额为负时不自动发起追偿或调整。脚本 PASS 仅代表输入可计算，不能证明政策资格、提交成功或已到账。
