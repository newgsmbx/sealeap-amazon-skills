# Amazon 促销自动下单库存预案 Playbook

## 适用问题

Use for 分站点大促排期确认、上线价格触发式自动下单或提醒功能后的调价预案、促销期库存断货风险排查. Do not use to lower list price without first confirming current stock coverage and the feature's live trigger rules on the target site.

## 输入证据

- marketplace、ASIN/SKU、库存阶段、补货与到仓时间
- 断货或备货前后的销量、流量、广告、自然位置和转化基线
- COGS、头程、仓储、平台费、退货和清仓成本
- 可比产品的成熟度、销量区间和需求趋势

## 决策路径

1. 促销开始前到目标站点后台核实本轮各站点的实际促销日程与规则版本，不沿用往期经验日期。
2. 确认目标市场是否已上线价格触发式自动下单或提醒功能，以及该功能当前识别的是标价还是叠加优惠后的实付价。
3. 核对每个可能触发自动下单的价格点位对应的现有库存与在途库存，估算若价位触发会消耗多少库存、是否会击穿安全库存线。
4. 调整标价前设定单次降价幅度上限与观察窗口，分批小幅试探而非一次性大幅降价，并预留暂停或恢复原价的操作路径。
5. 促销期内持续监控订单速率与库存消耗曲线，出现异常放量时立即核实是否为自动下单触发并评估是否暂停或调价。
6. 促销结束后复盘触发订单占比与库存影响，更新下一轮促销的价格与备货缓冲设置。

## 经验假设与降级规则

- 各站点具体促销日期、预热与正式期划分每轮都会调整，不作为固定日历使用，执行前以官方最新公告为准。
- 自动下单或提醒功能是否识别优惠券、秒杀价等叠加折扣，属于平台机制细节，需在目标站点当次核实，不能沿用此前版本的判断。
- 降价可能批量触发远超备货预期的订单，目前是行业观察到的待验证现象，实际触发规模因类目与关注量而异，需以自身账户监控数据校准。

- 出现固定阈值、平台算法解释或因果结论时，改为待验证假设，并用当前站点与账户数据校准。
- 数据源冲突时保留各自口径，不取没有依据的平均数，也不选择更好看的结果。
- 第三方工具不可用、额度不足或 schema 改变时，记录缺口并停止；不得伪造调用结果。

## 输出检查

- 分站点促销日程核对表
- 价格点位库存消耗测算
- 分批调价与回退预案
- 促销期订单异常监控记录
- 每项建议都能回指当前任务中的证据或明确假设。
- 对未授权的线上变更保留草案；用户已有授权覆盖明确对象、动作与预算时可执行，并记录实际结果与回读证据。

## 指标口径补充

- 所有比率先统一站点、货币、对象、流量范围与归因窗口；分母为零或缺失时记为不可计算，不能解释为零成本或无限效率。
