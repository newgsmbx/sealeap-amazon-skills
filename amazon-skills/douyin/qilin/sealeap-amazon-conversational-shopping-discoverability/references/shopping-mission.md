# 购物任务与商品证据映射

核验日期：2026-09-23。[Amazon 购物助手说明](https://www.aboutamazon.com/news/retail/amazon-rufus) 包含按用途、场合、比较及商品问题协助购物的能力，并注明 Rufus 于 2026-05-13 更名为 Alexa for Shopping。旧名可作为检索别名；站点/账户能力以当日页面为准。

本框架是独立的内容与测试设计，不是平台公布的排名因子、权重公式或保证被推荐的方法。

## 任务卡

| 字段 | 需要回答的问题 |
|---|---|
| 客户与时刻 | 谁在什么环境下作购买决定？证据来自真实需求还是推断？ |
| 要完成的任务 | 想完成什么动作，如何判断完成？ |
| 限制条件 | 尺寸、设备、年龄、空间、预算、维护及不适用情况？ |
| 商品证据 | 哪一条规格、说明书、实拍或测试证明适合？适用哪个子体？ |
| 内容位置 | 应放结构化属性、标题/亮点、五点、尺寸图、视频还是 A+？ |
| 验证问题 | 正向、比较、带限制和不适用的自然提问分别是什么？ |

需求来源与商品事实分别验证：商品能做到某事不证明市场需求高；搜索量高也不证明商品有该功能。没数据的任务假设标 INFERRED，不能编造频次。

## 操作

1. 从真实客服问题、搜索词、退货原因和评论主题生成任务卡；只读分析，不发布假问答或评论。
2. 每个任务拆为 supported / conditional / unsupported / unknown。未知不能进入肯定卖点；条件必须随表述一起出现。
3. 将可证信息分配到当前允许字段，保持子体和语言一致。只优化用户指定的内容范围，不强制扩写整套 Listing。
4. 图片/视频直接演示关键动作和限制，避免 AI 画面增加不存在的配件或效果。属性与视觉冲突先修事实。
5. 建立包含负向约束的查询集，记录站点、日期、登录/地域、原问题、返回内容、是否提及商品、事实准确性与证据。入口不可用则交付离线覆盖表，不伪造测试回答。
6. 多次观察保持查询与环境可比；推荐出现率是样本观察，不是全市场份额。点击/订单必须有对应一方数据才能评价业务结果。

## 交付模板

任务 → 来源等级 → 关键条件 → 商品证据 → 改写字段 → 未覆盖问题 → 测试方式。
示例必须明确为合成：若收纳盒只证实室内使用，户外防水任务应标 unknown/unsupported，不能为了覆盖该需求写“防水”。

最终分别报告内容覆盖、助手观察与经营结果，三者不能互相替代。
